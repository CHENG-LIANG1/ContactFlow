# ContactFlow 产品需求文档（PRD）

| 项目     | 内容                                    |
| -------- | --------------------------------------- |
| 产品代号 | ContactFlow                             |
| 文档版本 | v0.1                                    |
| 目标平台 | iOS（React Native）                     |
| MVP 时限 | 48 小时独立项目                         |
| 文档状态 | 可进入原型与开发                        |
| 核心原则 | AI 提议，用户确认，系统执行，结果可追溯 |

## 1. 背景与机会

聊天截图里经常已经包含下一步行动所需的信息，例如联系人姓名、电话、会议时间、地点和跟进承诺，但用户仍要在聊天、通讯录与日历之间反复切换和录入。

ContactFlow 将聊天截图转化为“可确认、可编辑、可执行”的行动卡片。它不只是对截图做问答，而是完成一个受控的 agent 闭环：

1. 理解截图和补充文字；
2. 识别值得执行的动作；
3. 用结构化卡片向用户说明动作内容和依据；
4. 仅在用户确认后调用设备能力执行；
5. 记录执行结果，并结合联系人历史生成有依据的洞察与建议。

## 2. 产品定义

### 2.1 一句话定位

把聊天截图变成安全、可确认的联系人和日程行动，并让每次互动沉淀为可控的关系记忆。

### 2.2 目标用户

- 高频通过微信、短信或其他聊天工具推进事务的个人用户；
- 需要维护客户、候选人、合作伙伴或朋友关系的独立从业者；
- 经常从聊天中创建日程、保存联系人或补全联系人资料的用户。

### 2.3 核心用户任务（JTBD）

当一段聊天包含明确的后续行动时，我希望系统替我识别和填好信息，但在真正修改日历或通讯录前让我核对，从而减少切换和录入，同时不失去控制。

### 2.4 产品原则

- **确认优先**：任何外部写操作都必须经过逐卡确认；分析不等于授权。
- **展示依据**：动作与洞察需要说明来自截图、用户补充还是已确认记忆。
- **最小记忆**：只保存完成产品价值所需的信息，不把模型推断当事实。
- **允许修正**：用户可以编辑动作字段、纠正联系人匹配并删除记忆。
- **失败可恢复**：权限拒绝、网络中断或系统写入失败时，不制造“已完成”的假状态。

## 3. MVP 目标与边界

### 3.1 目标

48 小时内交付一个可在 iOS 模拟器和至少一台真机开发构建上运行的演示版本，打通以下闭环：

> 上传聊天截图 + 补充文字 → 生成行动卡片 → 用户编辑/确认 → 写入日历或通讯录 → 生成联系人相关洞察

### 3.2 P0 范围

- 从相册选择 1 张聊天截图；
- 可选输入一段补充文字；
- 识别上下文、联系人候选与行动候选；
- 支持三类行动卡片：
  - 创建会议；
  - 创建联系人；
  - 更新联系人；
- 卡片支持确认、编辑、取消；
- 确认后调用 iOS 日历或通讯录完成写入；
- 展示每张卡片的执行中、成功或失败状态；
- 仅在行动成功后沉淀经过确认的联系人记忆；
- 基于当前上下文和联系人记忆生成 1～3 条有依据的洞察或建议；
- 提供联系人记忆详情页，可查看来源并删除单条记忆；
- 提供演示数据或 mock 模式，便于在没有真实联系人数据时测试。

### 3.3 P1（时间允许）

- 一次选择多张连续截图；
- 从系统分享菜单将截图发送到 ContactFlow；
- 联系人模糊匹配时展示多候选选择器；
- 行动历史筛选和失败重试；
- 删除原始截图、清空全部云端数据。

### 3.4 明确不做

- 自动发送消息、邮件或拨打电话；
- 未确认的自动执行或批量自动确认；
- Android 适配与上架级兼容性；
- 企业 CRM、团队协作、销售管道；
- 全量读取或上传用户通讯录；
- 长期保存完整聊天截图；
- 通用聊天机器人、开放式工具市场或复杂多 agent 协作；
- 通过聊天截图伪造不可验证的联系人事实。

## 4. 信息架构

MVP 使用三页主结构：

| 页面       | 主要内容                                     | 主要动作                     |
| ---------- | -------------------------------------------- | ---------------------------- |
| 处理       | 截图选择、补充文字、分析结果、行动卡片、洞察 | 上传、分析、编辑、确认、重试 |
| 历史       | 历次分析与动作执行记录                       | 查看详情、重试失败动作       |
| 联系人记忆 | ContactFlow 已确认的联系人画像与记忆         | 查看来源、删除记忆           |

设置入口放在联系人记忆页顶部，包含隐私说明、权限状态、演示模式、数据清理和模型服务状态。

## 5. 核心用户流程

### 5.1 首次使用

1. 用户看到价值说明和隐私承诺；
2. App 不在启动时索取通讯录或日历权限；
3. 用户选择“开始处理”，从相册选择截图；
4. 仅在用户确认某类动作并准备执行时，解释用途并请求对应系统权限。

### 5.2 从截图生成行动

1. 用户选择一张截图；
2. 用户可填写补充文字，例如“下周二上午，记得加上线上会议链接”；
3. 用户点击“分析截图”；
4. 页面展示上传、理解、匹配联系人三个阶段；
5. 系统返回上下文摘要、联系人候选和行动卡片；
6. 低置信度或缺少必填字段的卡片以“需补充”状态展示，不能直接确认。

### 5.3 确认并执行行动

1. 用户展开卡片查看字段、依据与可能影响；
2. 用户可编辑任何可写字段；
3. 用户点击“确认并执行”；
4. App 请求对应系统权限（若尚未授权）；
5. App 在设备端执行写入；
6. 成功时显示系统对象摘要；失败时显示原因和恢复入口；
7. 只有成功动作才会进入联系人记忆和洞察生成。

### 5.4 查看洞察

行动执行成功后，系统结合：

- 本次截图中的已确认信息；
- 用户对行动卡片的编辑结果；
- 该联系人的已确认历史记忆；
- 最近的已执行互动或会议；

生成 1～3 条建议。每条建议包含“建议内容、为什么、依据、下一步”，但不会自动再执行动作。

## 6. 功能需求

### 6.1 输入与分析

| 编号  | 需求                                             | 优先级 | 验收要点                                               |
| ----- | ------------------------------------------------ | ------ | ------------------------------------------------------ |
| IN-01 | 从相册选择单张 PNG/JPEG/HEIC 图片                | P0     | 选择后可预览、更换、移除                               |
| IN-02 | 输入最多 1,000 字补充文字                        | P0     | 空文本不阻塞分析                                       |
| IN-03 | 上传前统一转成 JPEG、压缩图片并移除非必要元数据  | P0     | HEIC 等输入完成兼容转换；长边限制在 2,048 px；方向正常 |
| IN-04 | 分析时展示明确进度和取消入口                     | P0     | 重复点击不会创建重复任务                               |
| IN-05 | 识别截图里的说话人、时间表达、联系方式和行动意图 | P0     | 输出符合结构化 schema；无法确定时返回缺失项            |
| IN-06 | 解析相对时间时使用设备时区和当前日期             | P0     | 卡片展示绝对日期、时间和时区供确认                     |
| IN-07 | 模型拒绝、超时或无有效动作时给出可理解反馈       | P0     | 不展示空白卡片或伪造动作                               |

### 6.2 行动卡片通用要求

每张行动卡片必须显示：

- 动作类型和状态；
- 关键字段预览；
- 识别依据，例如截图中的相关语义片段或用户补充；
- 置信度标签：高、中、低；
- 缺失字段或冲突提示；
- 编辑、取消、确认并执行按钮；
- 执行成功后的系统结果或失败原因。

状态流转：

`需补充/待确认 → 已编辑 → 执行中 → 已完成/失败`

用户也可以从待确认状态进入“已取消”。已完成动作不可再次直接执行，只能复制成新动作，防止重复写入。

### 6.3 创建会议

| 字段      | 要求                                             |
| --------- | ------------------------------------------------ |
| 标题      | 必填；默认根据聊天上下文生成                     |
| 开始时间  | 必填；必须展示绝对日期时间                       |
| 结束时间  | 必填；未提及时默认 30 分钟，并明确标注“系统默认” |
| 时区      | 必填；默认设备时区                               |
| 地点/链接 | 可选                                             |
| 参与人    | 可选；仅使用已确认的联系人或用户编辑结果         |
| 备注      | 可选；包含必要上下文，不复制整段敏感聊天         |
| 目标日历  | 必填；默认使用可写的默认日历，用户可切换         |

业务规则：

- 结束时间不得早于开始时间；
- 时间表达存在多个解释时必须让用户选择；
- 与已有日程冲突时给出提示，但允许用户继续；
- 创建成功后保存系统事件 ID 和执行时间；
- 失败时不写“已安排”记忆。

### 6.4 创建联系人

| 字段      | 要求                           |
| --------- | ------------------------------ |
| 姓名      | 至少一个姓名字段或组织名称     |
| 手机      | 可选；做格式标准化但保留原始值 |
| 邮箱      | 可选；校验基本格式             |
| 公司/职位 | 可选                           |
| 备注      | 可选；仅写入用户确认的摘要     |

业务规则：

- 在请求通讯录写权限前，先展示将写入的字段；
- 若手机号或邮箱与现有候选联系人匹配，优先建议“更新联系人”；
- 若只按姓名弱匹配，不自动合并；
- 创建成功后记录系统联系人 ID，但系统联系人仍以设备为事实源。

### 6.5 更新联系人

卡片必须同时展示“当前值”和“拟更新值”。默认仅 patch 有变化且经确认的字段，不覆盖卡片未展示的系统字段。

业务规则：

- 必须先绑定唯一的目标联系人；
- 多个候选时禁止直接确认，用户必须选择；
- 不允许把空值写入已有非空字段，除非用户明确选择“清除”；
- 成功后记录字段级变更摘要；
- 设备上的联系人在执行前已变化时，重新读取并提示冲突。

### 6.6 联系人匹配

匹配优先级：

1. 已绑定的系统联系人 ID；
2. 标准化手机号精确匹配；
3. 小写化邮箱精确匹配；
4. 姓名 + 公司组合匹配；
5. 仅姓名模糊匹配。

前 3 类可给出高置信候选，但仍需用户在卡片中确认目标；后 2 类若有多个候选，必须进入候选选择器。ContactFlow 不上传全量通讯录，只在设备端匹配，并只把必要的候选摘要用于本次确认。

### 6.7 历史记录

- 按分析批次展示时间、缩略图占位、动作数量与执行结果；
- 原始截图删除后仍保留脱敏摘要和动作审计记录；
- 可以查看当时的动作字段、用户编辑和执行结果；
- 失败动作可在重新校验后重试；
- 成功动作不提供“一键重试”。

## 7. Memory 设计

### 7.1 记忆分层

| 层级       | 内容                         | 是否可直接作为事实 | 示例                                  |
| ---------- | ---------------------------- | ------------------ | ------------------------------------- |
| 原始来源   | 截图、补充文字、分析时间     | 否                 | 某张聊天截图                          |
| 观察       | 模型从来源中提取的候选信息   | 否                 | “可能在下周二见面”                    |
| 已确认事实 | 用户确认或设备执行成功后形成 | 是                 | “与 Alex 的会议定于 8 月 25 日 10:00” |
| 关系摘要   | 从多个已确认事实压缩而来     | 有来源时可用       | “通常偏好工作日上午沟通”              |
| 用户偏好   | 用户明确设置或多次确认       | 是                 | “默认会议时长 30 分钟”                |

### 7.2 写入规则

- 模型提取结果先作为观察，不直接成为长期事实；
- 用户对动作字段的最终确认值，是事实候选；
- 外部写操作成功后，才把与结果相关的事实标记为已确认；
- 用户取消或执行失败的动作不产生完成型记忆；
- 每条记忆必须带联系人、来源、创建时间、确认方式和置信度；
- 关系摘要必须能追溯到一条或多条已确认事实；
- 用户可以删除单条记忆，删除后不再用于后续检索。

### 7.3 冲突与过期

- 手机、邮箱、公司等唯一或当前属性出现冲突时，保留历史但只标记一个当前值；
- 新值不能仅凭模型推断覆盖已确认值；
- 会议、承诺等事件型事实按时间自然归档，不覆盖；
- 推导型偏好设置 90 天复核周期；连续 3 次证据一致才可显示为“可能的偏好”；
- 原始截图默认分析完成后 24 小时删除，用户可立即删除；
- 删除联系人记忆时，不反向删除系统通讯录联系人，除非用户另行在系统中操作。

### 7.4 检索策略

MVP 不做全量向量数据库。先通过联系人 ID、标准化手机号/邮箱、时间范围和记忆类型做确定性检索，再只把最近且相关的已确认事实传给模型。这样更容易解释、测试和控制隐私。

## 8. 洞察与建议

### 8.1 输出格式

每条洞察包含：

- **洞察**：一句可验证的观察；
- **为什么有帮助**：与当前行动的关系；
- **依据**：最多 3 条已确认事实或本次确认字段；
- **建议下一步**：用户可自行采取的动作；
- **置信度**：高、中、低。

### 8.2 允许的示例

- “你与 Alex 最近两次沟通都安排在上午，本次选择 10:00 与既有习惯一致。”
- “该联系人缺少公司信息；这次聊天提到 Acme，但尚未确认，建议在会面时核实。”
- “上次已确认的待办是发送报价，本次会议备注可加入该事项以避免遗漏。”

### 8.3 禁止的输出

- 没有来源的人格、健康、财务或关系强度判断；
- 把单次聊天推断为长期偏好；
- 暗示系统已经完成尚未执行的行动；
- 使用已删除、未确认或属于其他联系人的记忆；
- 用“为了你方便”绕过用户确认继续执行工具。

## 9. 权限、隐私与安全体验

- 相册、通讯录和日历权限按需请求，并在系统弹窗前解释用途；
- 用户拒绝权限后仍可查看和编辑行动卡片，只是不能执行对应动作；
- AI 服务密钥不进入 App 包或客户端环境变量；
- 上传图片使用短期私有地址，不公开暴露；
- 日志默认不记录原始图片、完整手机号、邮箱或模型完整提示词；
- 所有云端数据按用户隔离；
- 设置页提供“删除原始截图”“清空 ContactFlow 记忆”“删除账户数据”；
- 动作执行日志记录谁、何时、确认了什么和执行结果，但不复制无关隐私数据。

## 10. 异常与空状态

| 场景                 | 产品行为                                         |
| -------------------- | ------------------------------------------------ |
| 截图模糊或无聊天内容 | 说明无法识别，允许换图或补充文字                 |
| 没有可执行动作       | 展示上下文摘要和“未发现明确动作”，不强行生成卡片 |
| 时间或联系人不明确   | 卡片进入“需补充”，高亮缺失字段                   |
| AI 超时              | 保留输入并提供重试；同一任务不重复扣写           |
| 网络中断             | 保留本地草稿；恢复后由用户重新发起               |
| 权限拒绝             | 说明系统设置路径；不把动作标为失败完成           |
| 日历/联系人写入失败  | 显示原始系统错误的友好映射，并允许安全重试       |
| 执行回执上传失败     | 本地保存待同步回执；不重复执行系统写入           |
| 联系人在设备端被删除 | 解除绑定并要求重新选择或创建                     |

## 11. 非功能需求

- 首屏在中端 iPhone 上 2 秒内可交互；
- 典型截图分析 P50 小于 8 秒、P95 小于 20 秒（不含弱网上传）；
- 所有外部写操作具备幂等保护；
- 关键按钮具备 VoiceOver 可读名称、状态和提示；
- 支持动态字体，核心确认流程在 200% 字体下可完成；
- 正文与背景对比度满足 WCAG AA；
- 网络失败不丢失用户选择的图片引用和补充草稿；
- 云端服务不可用时，演示模式仍可跑通 UI 和原生工具适配层测试。

## 12. 成功指标

MVP 以任务质量而非活跃规模为主：

| 指标           | 目标                                     |
| -------------- | ---------------------------------------- |
| 有效行动卡片率 | 测试集里应生成动作的样本中 ≥ 85%         |
| 必填字段准确率 | 明确出现在截图/补充文字中的字段 ≥ 90%    |
| 错误自动执行   | 0；所有写操作必须有确认事件              |
| 执行成功率     | 权限已授予且字段有效时 ≥ 95%             |
| 重复写入率     | 0                                        |
| 洞察可追溯率   | 100% 洞察至少绑定 1 条可展示依据         |
| 任务完成时间   | 从选择截图到完成一个动作的中位数 < 60 秒 |

## 13. MVP 验收场景

### AC-01 创建会议

给定截图明确包含“下周二上午十点聊 30 分钟”和联系人姓名，用户在上海时区于指定测试日期上传截图；系统生成带绝对日期、10:00～10:30、联系人和依据的会议卡。用户确认并授权日历后，日历中只出现一个事件，App 显示成功回执并生成带来源的会议记忆。

### AC-02 创建联系人

给定截图包含姓名和手机号，且设备中没有精确匹配；系统生成创建联系人卡。用户修改公司字段并确认后，通讯录出现一条联系人记录，最终记忆使用用户修改后的公司，而不是模型原值。

### AC-03 更新联系人

给定手机号能精确匹配现有联系人且截图包含新公司；卡片展示当前公司与拟更新公司。用户确认后只更新公司字段，原有头像、地址和备注保持不变。

### AC-04 信息不明确

给定截图只写“下周找时间聊”，系统不得生成可直接确认的会议卡；若生成候选卡，必须标记缺少具体日期和时间，并禁用执行按钮。

### AC-05 取消与失败不写记忆

用户取消卡片或系统写入失败时，不生成“已创建/已更新/已安排”的记忆，也不在洞察中引用该结果。

### AC-06 防重复

用户在执行中重复点击确认或 App 在回执上传前重启，恢复后不得在系统日历或通讯录创建第二份记录。

### AC-07 记忆冲突

已有确认公司为 A，本次模型从截图推断公司为 B 但用户未确认；联系人记忆仍以 A 为当前值，B 只作为本次未确认观察且不用于后续洞察。

### AC-08 权限最小化

用户只分析截图而未确认动作时，App 不请求通讯录或日历权限。确认创建会议时只请求日历权限，不请求通讯录写权限。

## 14. 48 小时交付建议

| 时间        | 交付                                               |
| ----------- | -------------------------------------------------- |
| 0～4 小时   | 工程初始化、数据契约、三条黄金测试截图、低保真交互 |
| 4～12 小时  | 截图选择/上传、分析接口、结构化行动卡片            |
| 12～22 小时 | 日历与通讯录适配器、权限流程、动作状态机           |
| 22～30 小时 | 记忆写入/检索、联系人详情、洞察生成                |
| 30～38 小时 | 错误恢复、演示模式、历史页、隐私设置               |
| 38～44 小时 | 单元/集成/E2E、真机验证、修复                      |
| 44～48 小时 | 云端测试环境、README、演示脚本和录屏               |

若时间不足，优先保证“创建会议 + 创建/更新联系人 + 确认门禁 + 执行后记忆”可靠；历史筛选、复杂候选匹配和视觉精修可以降级。

## 15. 待确认的产品决策

以下内容不阻塞 MVP，可在开发启动时按默认项执行：

| 决策           | 默认方案                               |
| -------------- | -------------------------------------- |
| 是否需要登录页 | 不做显式登录，使用匿名用户身份隔离数据 |
| 原始截图保留期 | 24 小时后自动删除                      |
| 默认会议时长   | 30 分钟，并在卡片上标注默认值          |
| 洞察生成时机   | 每个动作成功后生成一次，可手动刷新     |
| 云端区域       | 选择离测试用户最近且满足数据要求的区域 |
| UI 语言        | MVP 中文；数据模型保留国际化能力       |
